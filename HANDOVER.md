## 3. Versioning and the auto-upgrade (read before changing content)

- Every deploy bumps **`APP_VERSION`**. On the first request with a new version, `App::upgradeNow()` runs:
  `Schema::create()` → `JawaiGuide::ensure()` → `Articles::ensure()` → `safariOnlyUpgrade()` → `Demo::assignImages()`.
- `ensure()` methods **only insert missing pages; they never overwrite** a page (the owner may have edited it).
- To change text that is **already in the live database**, add an exact-phrase pair to one of the fix lists in
  `App.php` (`DISTANCE_FIXES`, `CONTENT_FIXES`, `PRIVATE_FIXES`, `SEO_FIXES`, `PRICE_FIXES`, `GUIDE_FIXES`).
  They run as SQL `REPLACE()`, so if the owner edited that sentence nothing happens (safe). `GUIDE_FIXES` skips rows
  that already contain the new text, so append-style fixes do not duplicate. Update the source text
  (`JawaiGuide.php` / `Articles.php` / `Seeder.php`) too, so fresh installs match.
- Old saved **settings** are replaced only through the `$old` needles map in `safariOnlyUpgrade()` (the saved value is
  deleted only if it still contains the old default wording).
- One-time actions use marker files in `private/storage/` (e.g. `.price-3999-v1`, `.footer-review-v1`,
  `.favicon-pack-v2`, `.email-log-cleared-v1`, `.indexnow-<version>`).

## 5. How to deploy

1. Commit to `main`, bump `APP_VERSION` when content or schema changes, push `main`, and force-push the same commit to
   `claude/peaceful-ptolemy-9jr1e9`. End commit messages with the attribution trailer the session asks for.
2. Run the FTP deploy (the `gh` CLI works in the agent container):
   ```bash
   gh workflow run deploy-ftp.yml --ref main -R mrsheoganj/captains-of-jawai \
     -f dry_run=false -f verify_tls=false -f refresh_text=false -f import_photos=false
   gh run list -R mrsheoganj/captains-of-jawai -w deploy-ftp.yml -L 1        # get the run id
   gh run watch <id> -R mrsheoganj/captains-of-jawai
   ```
   - `verify_tls=false` is **required**: GoDaddy's FTP certificate name does not match.
   - Leave `phone` and `whatsapp` empty, so the deploy never overwrites the owner's numbers.
   - `refresh_text=true` **replaces safaris, pages and FAQs with the seed text** (owner edits lost). Do not use it unless asked.
   - `import_photos=true` runs the image plan (only needed after changing `ImagePlan`).
3. **What the workflow does:** lftp mirror upload (never deletes server files; skips `private/config.php`,
   `private/storage/` and `public_html/uploads/`) → uploads a random token to `private/storage/deploy-token` → POSTs it to
   `/_deploy` (`DeployController`, valid for 15 minutes and single-use) → `Updater::run()` takes a DB backup
   (`private/storage/backups/`), migrates, sends IndexNow → the workflow checks the live homepage and booking page.
4. Read the log: `gh run view <id> --log` is sometimes empty; the GitHub MCP tool `get_job_logs` (job id from
   `gh run view <id> --json jobs`) works. Look for `Database updated to version X` and `IndexNow: N URL(s) sent (HTTP 200/202)`.

## 6. Agent environment notes (cloud container)

- The container **cannot reach captainsofjawai.com** (or most outside sites) directly: the proxy blocks them. Use the read-only
  workflows, which run on GitHub's servers and push their results to branches you can `git clone -b <branch>`:
  - `fetch-page.yml` (input `urls`, space-separated) → branch **`page-fetch`**: HTML, text, a full-page screenshot and
    **response headers as Googlebot**. Also works for DNS-over-HTTPS (`https://dns.google/resolve?name=…&type=MX`).
  - `snapshot.yml` → `site-snapshot` (text of every live page) · `image-audit.yml` → `image-research` ·
    `route-check.yml` (OSRM road distances from Bera) · `vehicle-photos.yml` → `vehicle-research` · `site-check.yml`.
- **Local test copy:** `php -S 127.0.0.1:8080 -t public_html private/cli/dev-router.php` (SQLite in `private/storage/`,
  demo admin `demo@captainsofjawai.com` / `Demo@Jawai2026`, admin at `/admin`). The server dies when the container resets, so
  restart it before each test. Do not use `pkill -f` with a pattern that matches your own shell command.
- **Browser tests:** Playwright at `/opt/node22/lib/node_modules/playwright` (Chromium preinstalled; never run `playwright install`).
- The local DB is not the live DB. Never copy local data to the server.

## 8. Rules that must not be broken

1. **Never touch SMTP / email server settings** (Admin → Email & SMTP) unless the owner explicitly asks. Templates are fine.
2. **Never overwrite or delete** `private/config.php`, `private/storage/` or `public_html/uploads/`, and never delete files on the server.
3. **No invented reviews or testimonials**, and no "verified", "official" or "guaranteed sighting" claims.
4. **Never put the admin path** (`pk-admin`) in robots.txt, the sitemap or public pages.
5. **CC BY / BY-SA photos need credit:** `/photo-credits/` lists only photos in use; keep the footer link.
6. **Never store or use the leaked SSH private key**, and do not commit secrets.
7. **The owner asked for no visual or UI changes** to existing pages unless they request them. SEO work stays in titles,
   descriptions, structured data, sitemaps and new pages using the existing templates.
8. The user communicates in short, informal English and wants things done end to end: implement, test (local and live),
   deploy and report plainly. Ask only for genuine business facts (prices, phone numbers and so on).
